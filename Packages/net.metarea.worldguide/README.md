# MetaRea World GUIDE

## 0.17.1の変更

VCC配布ZIPへ本体Coreを直接収録しました。0.16／0.17から更新するとき、Unityの初回インポートより後に本体を展開する待ち時間がなくなり、元プレハブが一時的に見つからないエラーを防ぎます。既存の本体GUID、設置用プレハブ、シーン設定、お気に入り保存データを維持します。

Unity起動後の処理は説明書と導入記録だけを更新し、本体の展開・削除・上書きを行いません。本体への独自編集はVCCのパッケージ更新で置き換わるため、独自設定はAssets側のプレハブ・UserContentに保存してください。

0.12以前のAssets内に本体がある構成からは、先に0.17.0へ更新し、Unityで既存のバックアップ付き移行を完了してから0.17.1へ更新してください。0.13〜0.17の移行済みプロジェクトと新規導入では直接導入できます。

## 0.17.0の変更

- お気に入りの表示形式を「フォルダ形式／ワールド一覧」から選択できます。初期値はフォルダ形式です。一覧は全フォルダの登録順に並び、同じワールドは最初の1件だけを表示します。切替で登録データは削除されません。
- フォルダのワールド件数を非表示にし、自由入力の説明文へ置き換えました。空欄なら何も表示しません。
- 新規配置時の初期表示を4枠にしました。設置済みボードで明示的に選択した表示形式は保持します。
- TOPのworld型広告はv4配信でも直接ポータルを要求します。詳細閲覧型とバナーは従来どおり詳細を開きます。
- 直接ポータル広告の受付は全体のポータル要求へ1回、別通信で広告別内訳へ記録します。詳細閲覧には加算しません。広告詳細閲覧は同一広告・各端末の共有管理内で30分に1回の既存抑制を維持します。
- 広告別ポータル内訳と新統計画面にはArchiveパッチ051が必要です。計測は送信失敗時に再送しないため、全体と広告別内訳の件数が一致しない場合があります。Editor／ClientSimからは送信しません。
- TOP広告を追加した後は、広告設定だけでなく画像を含む新しい配信セットの生成・公開も必要です。VCC更新だけではArchive本番の更新や配信公開は行いません。

VCCで更新し、必要な設定を確認してシーンを保存後、設置先ワールドを再公開してください。

## 0.16.0の変更

- 通信失敗の再試行を5～10／10～20／20～40秒に分散し、join直後の復帰を高速化。
- 4回失敗後は60～90／120～150／240～270／270～300秒の復旧待ちへ移行。手動再試行も同じ待機を守ります。
- Archive 049の混雑応答（reason: busy）に対応。有効なmanifestに基づく画像取得はJSONの混雑待ち中も継続します。旧Archiveの待機応答は従来どおり処理します。
- 初回取得の0.1～0.75秒分散、SDKに合わせた5.1秒間隔、抽選の300秒期限を維持。失敗中は先読みを抑え、既存の成功表示を保持します。
- 設置済みワールドへの反映にはVCC更新後のワールド再公開が必要です。

## 0.15.0の変更

お気に入りはフォルダ一覧（2列×4段）から各フォルダのワールド一覧（8件/ページ）を開く構成になりました。Unityの「お気に入りワールド設定」で、フォルダとワールドを折りたたんで編集できます。追加・改名・並べ替え・フォルダ間移動・削除に対応し、同じワールドを別フォルダにも登録できます。フォルダ削除時は移動先を選び、中身を移すか一緒に削除するか確認します。

旧登録は「フォルダ1」へ自動移行し、ID・タイトル・作者名・登録順を維持します。移行前のJSONはプロジェクト直下のMetaReaWorldGuideBackups/Favoritesに保存します。保存データは引き続きAssets/MetaRea_World_GUIDE/UserContentにあり、パッケージ更新の対象外です。Unityでシーンを保存し、ワールドを再公開してください。

通常ワールドのカード・横長一覧にPC/Android/iOSの対応状況（✓対応・—非対応・?未確認）を表示し、詳細画面では状態を文字で表示します。お気に入りには対応端末を表示しません。横長一覧のタイトル・紹介文は最大各2行、作者名は表示幅で省略します。詳細画面の作者名が長い場合はスクロール可能な本文にも全文を表示します。フォントは変更していません。

配信のplatformSupport: { pc, android, ios }の各値true/false/nullを利用します。項目がない旧配信は未確認とし、AndroidからiOSを推測しません。Archive側は更新パッチ048の適用が必要です。GUIDEのVCC更新だけではArchive本番へパッチを適用しません。

本体はPackages/net.metarea.worldguide/Core、設置用Prefab VariantとUserContentはAssets/MetaRea_World_GUIDEへ配置します。
本体はVCCパッケージに直接含まれます。Assetsに本体がある旧構成の移行は0.17.0で先に行い、同じGUIDの旧本体と新本体を同時にインポートしないでください。

SDKはcom.vrchat.worlds >=3.10.5。0.13.0はguide-v4配信とBOOTHリンク・プリセット配色に対応しています。

0.13.1: オンライン用ボードの不要なサンプル・編集プレビュー画像をビルド時に除外します。お気に入り登録はAssets/MetaRea_World_GUIDE/UserContent/Favoritesへ保存し、更新後も保持します。関連付けはシーンを保存して確定してください。

## 0.14.0の変更

匿名統計をschema 2へ移行しました。board_readyは同一クライアント・共有管理単位の表示準備完了初回、portal_request_acceptedは操作側の受付、portal_owner_acceptedは所有者側の受付を表します。通常・広告・お気に入りのポータルに対応します。閲覧人数・ポータル表示成功・移動成功は測定しません。schema 1の通信結果イベントは送信しません。

設定の「統計の設置先コード」は英数字・_・-の1～64文字で、未設定はunknownです。「統計の環境」は本番(production)・テスト(test)・未分類(unknown)から選びます。同一シーンの全ボードで揃えてください。コードは秘密情報ではなく、公開可能な設置先分類です。ユーザーID・セッションID・ワールドIDを追加送信しません。1台でも既存の統計設定を無効にすると共有管理全体の送信を止めます。

Editor/ClientSimでは統計および広告クリックを送信しません。送信フラグはビルド用シーンコピーだけで有効になります。VRChat内のテスト用ビルドは環境をtestに設定してください。通常の配信JSON取得は引き続き発生します。

操作は60秒単位で統合せず、各受付を64件のFIFOキューへ保存します。送信は開始60～75秒後から最短10秒間隔、同一クライアントの共有管理単位で最大128件、待機期限300秒、再送なしです。読み込みを優先するため、短時間の滞在・通信不調・期限切れ・上限超過では未送信が発生します。Web側は受信件数として表示し、真の利用総数や成功率とは区別してください。広告詳細の既存30分重複抑制は別系統のままです。

受信契約: GET /api/udon/telemetry?schema=2&version=0.14.0&event=board_ready|portal_request_accepted|portal_owner_accepted&site=コード&environment=production|test|unknown&protocol=v2|v3|v4|unknown。protocolはイベント受付時に固定します。WEB側の更新パッチ047適用後からschema 2を受信できます。GUIDEをVCCで更新し、統計設定を反映してワールドを再公開してください。047の本番適用はこのパッケージ公開では実行しません。再送識別子を持たないためサーバーは個人単位の重複排除を推測せず、統計URLをキャッシュしないでください。


0.17.2: 広告ありの4枠表示で写真を拡大。分類見出しは写真左上に小さく表示し、ワールド名は写真下部へ重ね、文字幅に合わせた半透明・角丸の黒背景と薄い影を付けます。広告なし・2枠表示の配置は維持します。
