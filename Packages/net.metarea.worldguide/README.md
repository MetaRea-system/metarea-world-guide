# MetaRea World GUIDE

VRChatワールドに設置するワールド紹介ボードです。1つのプレハブで標準・4枠・お気に入りを切り替えられ、8種類の配色プリセットを収録しています。

## 表示モードの選び方

| 表示モード | 向いている使い方 | 表示内容 |
| --- | --- | --- |
| 標準 | 大きな写真で、その日のワールドを紹介したい | 今日のランダムワールド①・② |
| 4枠（many） | 一度に4つの候補を見せたい | 2列×2段。今日の①・②、紹介最新ワールド、おすすめランダムワールド |
| お気に入り | 設置者が選んだワールドを案内したい | 登録したワールドの一覧。クリックでポータルを作成 |

表示形式はUnityのInspector「表示形式」で指定します。ワールド内に標準・4枠の切り替えボタンはありません。お気に入りは既存のナビゲーション行の5番目のボタンで開きます。画面は元の800×1350の寸法です。

ルートで位置・大きさ・配色を調整し、Portal Anchorでポータルの出現場所を指定します。「お気に入りワールド設定」で登録内容を編集してください。内部UIはEditor上で誤編集を防ぐ保護をかけています。ルート・Portal Anchor・お気に入り設定は編集できます。この保護はUnity上の操作ミスを減らすためのもので、改変を完全に禁止するものではありません。

Unity上の写真と「ワールド名」「ワールドの説明文」は設置確認用です。実際のワールドでは配信内容に置き換わります。取得中は黒背景・白文字の小さな「読み込み中」画像と水色の動く点を表示し、画像がない場合と取得に失敗した場合は別の案内を表示します。many版のおすすめ枠、おすすめ・ランダムの一覧でも取得中の状態を確認できます。

## 導入

VCCでMetaReaのVPMリポジトリを追加し、このパッケージをワールドプロジェクトへ導入してください。Unity 2022.3.22f1 / VRChat Worlds SDK 3.10.5で確認しています。

`Packages/net.metarea.worldguide/Runtime` の `MetaRea World GUIDE` プレハブをシーンへ置きます。子オブジェクトの「お気に入りワールド設定」で登録内容を編集します。設定後にシーンを保存し、Build & Testで確認してください。画像・情報の表示にはVRChatの Allow Untrusted URLs を有効にしてください。配布プレハブは統合版のみです。表示形式（2枠／4枠）とお気に入り（有り／無し）は独立して設定できます。お気に入り無しではボタンを隠し、残り4ボタンを均等に配置します。

広告をクリックした場合は、その詳細画像を次の取得で最優先します。通信中の画像とSDKの取得間隔は維持します。通常の画像の取得順はデイリー → TOP広告 → 下部バナー → ランダム → ピックアップ → 広告詳細の先読みです。同時要求を増やさず、1件ずつ取得します。初回の抽選要求は先行画像の取得完了または失敗後に開始し、待ち時間で抽選の有効期限を消費しないようにしています。

## 複数ボード

同じシーンのボードは、自動作成される `MetaRea World GUIDE Shared Data` を通じて一覧と抽選結果を共有します。このオブジェクトは削除・非表示にしないでください。各ボードのタブ、ページ、詳細表示は独立しています。配信設定を変更した場合は、MetaReaメニューの「複数ボードの共通データ接続を更新」を実行してください。設定が異なるボードを混在させるとビルド時にエラーになります。

抽選画像のURLが期限切れになった後の途中参加者には一覧情報だけを表示し、次の再抽選で画像も更新します。

## スポンサー広告

World Archive管理画面の先頭で「ワールド広告」「画像広告」「画像＋ワールド広告（高級プラン）」のいずれかを選択します。TOPのスポンサー枠では、ワールド広告はクリックするとポータルを出し、画像広告は詳細画像を表示します。画像＋ワールド広告は詳細画像と「PORTAL この世界へ」ボタンを表示します。

TOP広告と下部バナーは掲載先を分けて設定できます。TOP専用の画像は下部バナーには混ざりません。下部バナーからは画像を開き、ポータルボタンはTOPから複合広告を開いた場合に表示します。掲載終了・停止、または配信状態を確認できない場合は広告を非表示にし、開いている広告詳細も閉じます。既存の通常バナーと旧ワールド広告データにも対応しています。

対応版では最大16件を扱います。TOPは同じ広告が左右に重ならないよう抽選します。管理者が指定した表示比率は抽選時の相対的な重みで、表示回数を保証するものではありません。金枠は外観の設定で、枠だけでは抽選確率は変わりません。掲載内容や比率の変更は再入場して新しい配信を取得した後に反映されます。

## 見た目とリンク

ルートのInspectorで配色プリセット、タイトルとリンクの色を設定できます。ミッドナイトではアーカイブの公式ロゴの元の色を使用します。右上のXとワールドアーカイブのロゴを押すと、それぞれのURLを表示します。

開発時の詳しい設定は `Runtime/README.txt` を参照してください。

## 匿名統計

公式Feed URLにはインストール済みパッケージ版をEditorで付加します。既存ボードもビルド時に共通データ側へ反映されます。独自Feed URLは変更しません。サーバーで数えられるのは到達したFeed要求で、利用人数や全端末の読込回数ではありません。

匿名操作統計は固定URLで読込結果、最初の有効ボード表示、ポータル要求を送ります。広告詳細は下記の詳細画面表示時に別集計します。個人・端末・設置場所・広告・ワールドの識別子は含めません。ボード表示は視線や注視の測定ではなく、ポータル要求も移動成功の確認ではありません。各クライアントの共通データに集約し、最初のFeed結果と掲載状態結果は各1件、ボード表示は1件、操作は同種60秒以内をまとめます。初回は60秒後以降、通信中は後回しにし、60秒以上の送信間隔、滞在中最大12件、再送なしです。短時間退出・通信失敗・キャッシュ・上限で減る参考値であり、成功率やCTRの厳密な計測には使えません。

Inspectorの「匿名の操作統計を送る」を無効にすると追加送信を止められます。同じシーンのいずれか1台が無効なら全ボードの操作統計が停止します。通常のFeed取得のサーバー側集計は継続します。追加統計APIの反映前でも、その失敗はワールド一覧や広告の読込エラーには扱いません。

## 4枠（many）表示

統合プレハブのInspectorで「4枠（many）」を選ぶと、TOPを2列×2段で表示します。上段は本日のランダム①・②、下段左は現在の配信一覧の新着先頭、下段右は共有おすすめ抽選の先頭を表示します。抽選中・候補なしの場合はその状態を表示します。詳細画面、ポータル、タブ、広告、バナー、配色設定は通常版と共通です。

## 広告詳細の先読み

### 配信用シートの縮小（0.8.6以降）

Archiveパッチ36対応の配信では、下部バナーは768×128px、QRは256×256pxを維持し、16広告を2048×2048pxの1枚に収めます。大画像は672×567px、3列×3段の9広告を2016×1701pxの1枚に収め、16広告でも2枚です。元のアップロード画像は保持し、ワールド内の表示サイズも変えません。細かい文字の読みやすさは広告デザインと表示距離に依存します。

公式Feedに `topImage=1&bannerLayout=3&detailLayout=2` を付加し、新形式は別snapshot番号で取得します。旧形式の配信にも対応します。適用にはGUIDE更新後のワールド再ビルドとArchive側更新が必要です。

詳細画面を開く前から、表示用の大きな広告画像を最も低い優先度で取得します。その中ではTOPに表示中の広告を優先し、複数ボードで必要な画像シートを共有します。取得中は黒背景の「読み込み中」を表示し、小さなバナーを代用しません。

計測用の1×1ドット画像は取得しません。先読み時もクリック時も広告詳細の画像計測は送信しません。

## 広告詳細の閲覧数（参考値・実機通信未確認）

この機能には、対応する更新版GUIDEでワールドを再ビルドすることと、Archive側のパッチ35適用の両方が必要です。パッチ35は34適用後にサーバー管理者が適用します。サーバーだけ更新しても既存ワールドには計測は追加されません。GUIDE 0.8.6に含まれます。相互データ検証は完了していますが、実VRChatクライアントからの計測通信は未確認です。

詳細画面を開いたときだけ、固定URLの文字列GETを使って記録します。計測用の画像は取得しません。同じ広告は端末内の共通データで30分に1回までとし、TOPカード枠・下部バナー枠・複数ボードをまたいでも重複させません。広告IDが同じなら掲載スロットや内容の更新でも抑制を維持し、最初に開いた枠へ記録します。直接ポータルを出すだけの操作・先読み・画面再描画は数えません。

個人IDは使用しません。再入場で記録がリセットされるため正確な人数ではありません。匿名統計OFF、URL未許可、通信失敗、退出、キャッシュ、送信上限で欠落する参考値です。5.1秒以上の送信間隔、キュー32件、滞在中128件、待機120秒、再送なし。実VRChatクライアントから新しい計測URLへの通信は未確認です。
